# Copy audit — November 2026

Player-visible copy rewrite for the ordinary play loop. Scope: string literals and JSX text in
`src/App.tsx`, `Inventory.tsx`, `AdventureResults.tsx`, `AccountSessions.tsx`, `NativeExpeditions.tsx`,
`NativeWardrobe.tsx`, `NativeLevelRewards.tsx`, `AuraClaims.tsx`, `PendingNativeTransactions.tsx`,
`NativeMarketPanel.tsx`, `MapNotes.tsx`, `PickupSummary.tsx`, plus player-facing error messages in
`server/game.mjs` and `server/index.mjs`. Logic, class names, test fixtures and the
CreatorCommunity / NativeTasks / NativeStaking panels were not touched.

Line numbers refer to the file **before** this change (`git show HEAD:<file>`; for `server/index.mjs`
`git show 00516f2:server/index.mjs`, because commit b0762b5 from a parallel session swept this file's
copy changes into its own commit while this audit was being prepared). Rows with the same
reason inside one file are grouped; each `<br>`-separated line in a grouped row is one string.

## Rules applied

1. Short and concrete: in-loop copy is at most two short sentences per state; policy prose moved to
   `Details`/Advanced or cut to one line.
2. Newcomer vocabulary (from `docs/UI-AUDIT-2026-11.md` row 12): wallet → account; transaction →
   receipt / "sent" / "confirmed"; testnet → omitted (Advanced says "test network"); mint / NFT /
   on-chain → "secured" / "Secured collection"; demo GOLD → practice GOLD (matches the existing
   `Practice ledger` / `Practice outfit` / `Practice GOLD market` labels); checkpoint / marker → stop.
   Chain words remain only inside Profile → Advanced, the external-wallet dialog, and `Details` /
   `Reviewed terms` disclosures.
3. Light Aavegotchi-style lore, used sparingly: the explorer is a friendly ghost, an Aura is the glow it
   wears, the city is a haunt to explore (welcome screen, guide greeting, empty states, note placeholder).
4. Consistent verbs: Start exploring, Walk there, Open chest, Confirm visit, Confirm stop n, Try it on,
   Equipped, Reward collected, Secured, Nearby discoveries, Closed for today, Checking visit….
5. Server errors are one sentence with a next step ("Get a bit closer to pick up this coin.").
6. Required disclosures stay, in one line: practice GOLD is play money with no monetary value; GPS is
   browser-reported and not verified; distances are straight lines; the shared GOLD prize pays once;
   securing an Aura holds up to 0.05 test NEAR for storage.

## Left unchanged on purpose

- `server/domain.mjs` `validateFix` messages ("Move closer to the item.", "Wait for a more accurate GPS
  fix.", "Your location fix is no longer current.") reach players as toasts for GPS play but the file
  was outside the allowed scope. Proposed: "Get a bit closer to open this chest." / "Get a bit closer
  to pick up this coin." (needs the target kind passed in), "GPS is too rough right now (±35 m needed).
  Step into the open and retry.", "Your GPS fix is stale. Retry location."
- `src/native-objective.ts`, `src/pickup-feedback.ts`, `src/adventure-results.ts`, `src/api.ts` carry
  player-visible labels (objective card messages, pickup announcements, "Result receipt unavailable")
  but are `.ts` modules, outside the `.tsx` scope.
- `CreatorCommunity.tsx`, `NativeTasks.tsx`, `NativeStaking.tsx`, `NativeProfile.tsx`,
  `NativeEconomyPanel.tsx`, `NativeCollectionControl.tsx` (default-off or Advanced) were excluded.
- Advanced-only wording keeps its technical words: the external NEAR wallet dialog (`Choose a NEAR
  wallet`, `Your keys stay in your wallet…`), Welcome → Advanced, Rewards → Practice → `NEAR account`
  section, Game economy → `Verified on NEAR` links (`Aura NFT contract`, `transfer NFT`), the
  `Reviewed terms` disclosure in receipt recovery (`Contract`, `Method`, `Attached deposit`, `Gas
  limit`, `NEAR testnet`), and the connector footer `QuestLayer · NEAR testnet`.
- `Link Aavegotchi wallet` (Inventory → Original Aavegotchi look) keeps "wallet" because the player
  really has to open an EVM wallet app; it sits inside a `Details` disclosure.
- Server messages kept a word that an existing test matches on, instead of changing the test:
  `Another explorer …` (`tests/game.test.mjs`), `… no longer available …` (`tests/game.test.mjs`),
  `… the destination …` (`tests/city-world.test.mjs`), `Enter the marked zone …`
  (`tests/city-world.test.mjs`). No test expectation was changed.
- `Check claim` (AuraClaims, NativeLevelRewards) stays as the button name because toasts refer to it by
  name; `claim` is otherwise avoided.
