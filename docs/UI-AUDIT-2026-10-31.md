# QuestLayer interface audit and staking revision

31 October 2026. Source audit and implementation handoff for W02/W05. This is not a claim that the complete interface, a physical phone, or the live staking cycle has passed acceptance.

## Player problem and scope

The user needs an exploration game whose next action is apparent. The source before this pass stacked native rewards, native staking and the demo wallet into one Wallet view. Each financial feature supplied its own explanatory panel. Useful controls competed with setup, protocol and accounting copy before the player had chosen an activity.

This subtask changes only `src/NativeStaking.tsx` and its new scoped `src/native-staking.css`. App navigation, Explore, native expeditions, inventory and global styling are owned by the coordinating implementation. The review findings below describe the source at the start of this pass; concurrent changes must be checked against the final combined app.

## Hierarchy alternatives

| Composition | Assessment |
| --- | --- |
| All positions, deposit inputs, exit buttons and setup explanation expanded | Preserves discoverability, but repeats the information density that prompted the revision. |
| A separate modal wizard for every deposit, exit and setup | Controls the amount of text shown, but adds modal navigation, focus management and more interruption to a small optional feature. |
| Compact position rows, deliberate inline Manage and Create disclosures | Selected. A player sees holdings and pending state first, opens the position they want, and encounters setup cost/acknowledgement at the creation decision. Native disclosure controls provide keyboard operation without inventing a modal system. |

## Broader priorities for the combined app

These are source findings and proposed directions, not additional work claimed by this subtask.

1. **P0: separate player intents in Wallet.** `App.tsx` previously mounted `NativeExpeditions`, `NativeStaking` and `WalletPanel` together. The player should choose rewards, optional staking or demo funds rather than scroll through all three. Preserve mode/network labels.
2. **P0: put native adventures into the exploration loop.** Keeping the actual funded quest board only in Wallet makes the game feel like a collection of protocol demos. Focus a real target on the map, show one objective and expose the next check-in. Do not let arena movement authorize physical rewards.
3. **P0: review complete states rather than fewer words alone.** Verify loading, too far, inaccurate GPS, pending, already claimed, expired and failure across the authoritative quest response. An icon cannot replace a reason a disabled button is unavailable.
4. **P1: inventory before integration.** `Inventory` in `App.tsx` shows the character but mounts native content and an original-asset connection section before all ordinary collection actions. Equipment should remain the first useful choice; Base linking belongs in a deliberate secondary disclosure. Keep owned Base appearances read-only.
5. **P1: reduce repeated interface headings.** Page header, feature header, testnet banner and explanatory paragraph should not restate the same information. Keep one mode label and add only the context specific to the current action.
6. **P1: review the short phone landscape layout.** A smaller font is not an answer to a short viewport. Let deliberate detail/form views scroll and verify that close/back/primary actions remain reachable with the keyboard open.
7. **P1: reduce global style layering.** `style.css` contains early rules with 13 px paragraphs/11 px small text and later token/target overrides. New scoped components should declare their own readable roles; a later cleanup should reconcile old selectors after rendered evidence rather than merely add more overrides.
8. **P1: retain an authored object system.** Utility icons can simplify navigation and actions, but chest, coin and Aura visuals should continue using game artwork rather than replacing them with utility symbols.

## Verification and remaining evidence

- The TypeScript stage of `npm run build` passed on this subtask's change.
- Existing `tests/native-vault-quote.test.mjs` passed, 2/2: exact amount parsing and quote network/signer/receiver/method/deposit binding.
- The first combined Vite build encountered a concurrent-work dependency: `NativeExpeditions.tsx` imported a not-yet-created `play-ui.css`. The coordinating agent must rerun the combined build after its stylesheet lands. This is not a staking type error.
- Code retains the existing request shapes and eligibility guards for create, deposit, exit, withdraw, pool update/advance, registration and refund. No contract, API or economic formula changed in this subtask.
- Contrast calculations for the opaque scoped token pairs are implementation checks only. They do not establish rendered contrast under every surrounding app state.
- No browser was operated by this subtask. The coordinating agent owns rendered screenshots and interaction checks. Required cases: 360/390 px portrait, short landscape, desktop, 200% text, deposit input with keyboard, keyboard-only disclosures, no-wallet/empty state, setup acknowledgement, malformed amount, pending transfer, unlocking, ready withdrawal, registration retry and refund pending.
- Real Safari/iOS and Chrome/Android hardware testing remains required. Source review and desktop responsive screenshots cannot establish those results.

The revised staking surface is implemented; the broad priorities above are proposals unless the combined delivery records their separate implementation and evidence.
